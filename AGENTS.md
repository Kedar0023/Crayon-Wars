# Agent Instructions

- Use **only `bun` and `bunx**`; never use `npm`, `npx`, or `yarn`.
- Use only single-line `//` comments; never use `/* */` or other multiline comments.
- Add at most one concise explanatory comment above complex code; avoid unnecessary comments.
- Add short end-of-line comments only to clarify unique syntax, non-obvious logic, or ambiguous code.
- Separate distinct functions or logic blocks with a blank line, `// ----------------`, and another blank line.
- Never create log files.
- Never run `git status`.
- Prefer the latest stable syntax and APIs for the chosen stack (e.g., React, Tailwind CSS); avoid deprecated or outdated patterns.
- Keep code modular, readable, and consistent with existing naming conventions.
- Do not generate documentation, test files, or other artifacts unless needed or requested.
- Inspect only relevant files, use targeted diagnostics, avoid redundant commands and repeated file reads, and summarize results concisely. Run builds only when necessary.
